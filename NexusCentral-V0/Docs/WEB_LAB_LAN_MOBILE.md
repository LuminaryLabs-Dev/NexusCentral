# Nexus Web Lab LAN + Mobile Plan

## Target

Nexus Web Lab should be reachable from a phone on the same LAN as a chat-first mobile UI, with the file tree available as an overlay.

## Where Settings Fit

- `Desktop/Services/LanRoutingSettingsService.cs` owns durable LAN settings: advertised host, control-plane port, LAN exposure flag, and shared token.
- `Desktop/Services/IntegrationServer.cs` owns CORS for NexusCentral API routes. It allows loopback origins by default and LAN Web Lab origins only when LAN exposure is enabled. It does not emit wildcard CORS.
- `Desktop/Services/NexusWebLabService.cs` owns Web Lab LAN launch behavior. It binds Next.js to `0.0.0.0`, advertises `http://<lan-ip>:3015`, and proxies API calls back to `127.0.0.1:3005`.
- `NexusCentral-WebHost/frontend/next.config.js` owns browser route rewrites from `/api/lab/*` to the desktop integration API.
- `NexusCentral-WebHost/frontend/public/app.css` owns responsive/mobile presentation.

## LAN Flow

```text
Phone browser
  -> http://<lan-ip>:3015/?mobile=1&k=<web-lab-mobile-key>
  -> Next.js Web Lab frontend
  -> /api/lab/* rewrites server-side
  -> http://127.0.0.1:3005/nexuscentral/*
  -> NexusCentral IntegrationServer
```

## CORS Rule

The normal mobile path is same-origin to the Next.js frontend and uses server-side rewrites, so browser CORS should not be involved. CORS still belongs in `IntegrationServer` for direct API tools, browser diagnostics, and future non-Next clients.

## QR Security Rule

The QR code must not expose the NexusCentral LAN routing token. It carries only a short-lived Web Lab mobile access key generated by `NexusWebLabService` when Web Lab starts. Next.js middleware requires that key for non-loopback access to `/` and `/api/lab/*`, then stores it in an HTTP-only same-site cookie for the phone session.

If the QR is photographed or shared, it grants Web Lab access until Web Lab restarts and rotates the key. Raw NexusCentral control-plane routes still require the separate `X-NexusCentral-Token` when accessed over LAN.

## Mobile UI Rule

The desktop UI keeps the full IDE layout. Mobile mode uses `?mobile=1` or narrow viewport CSS:

- Chat is the main screen.
- File tree is hidden by default.
- `Files` opens the explorer as a left overlay.
- Editor and interaction panes are hidden on phone.
- `Mobile QR` on desktop generates a local QR for the LAN mobile URL with the mobile access key.
